# Scheduling Verification

## Automated checks

```powershell
npm test
npm run lint
npm run build
```

The scheduler edge-case tests call the real FCFS, non-preemptive SJF, and Round
Robin functions. Expected results are hand-calculated rather than generated by
the implementation being tested. They cover shuffled arrival times, an idle gap
between processes, initial idle time, a single process, per-process metrics, and
averages from the generated schedules.

The application integration tests use Vitest, jsdom, and React Testing Library
to select policies, edit inputs, run simulations, and check chart intervals,
quantum-expired markers, table values, and rounded averages. They also verify
invalid inputs, stale-result clearing, reruns, and manual-input workload rejection.
These tests check DOM output; visual layout and screenshot capture still require
the browser walkthrough below.

## Calculation conventions

- Completion time (CT) is the end of a process's last CPU interval.
- Turnaround time (TAT) = CT - arrival time.
- Waiting time (WT) = TAT - burst time.
- Each average = sum of the per-process values / process count.
- Round Robin uses quantum 2 in the examples below. Arrivals during a time slice
  join the queue before the unfinished process is re-enqueued.
- Idle time before a process arrives is not part of that process's waiting time.
- Times are abstract time units. Context switches have no simulated time cost.

| Process | Arrival | Burst |
| --- | ---: | ---: |
| P3 | 11 | 2 |
| P1 | 0 | 5 |

Expected CPU intervals:

## Input and workload boundaries

The GUI validates manually entered process rows before scheduling:

- At most 100 processes, with non-empty, unique IDs.
- Arrival time: an integer from 0 to 1,000,000 inclusive.
- Burst time: an integer from 1 to 1,000,000 inclusive.
- Total burst time: at most 1,000,000 across all processes.
- Quantum: a positive safe integer (at most Number.MAX_SAFE_INTEGER).
- Round Robin workload: sum of ceil(burst / quantum) for each process must not
  exceed 10,000 CPU slices. Idle blocks are additional and bounded by the number
  of processes. A larger quantum can resolve a slice-limit error.

Unsafe integers and digit strings that overflow to Infinity are rejected before
scheduling. The time and count limits also bound the final schedule time to at
most 2,000,000 and sums of WT/TAT to at most 200,000,000, safely within exact
integer arithmetic. The scheduler functions otherwise expect validated process
inputs; GUI workload limits are enforced before calling them.

## Browser walkthrough and screenshot

1. Run `npm run dev` and open the local URL printed by Vite.
2. Click **Start simulation**, select FCFS, and enter Scenario B in the listed order.
3. Click **Run simulation**. Compare every table value with Scenario B.
4. Confirm a striped **Idle** block appears from 5 to 10, the chart labels and
   time boundaries are readable, average WT is 0.67, and average TAT is 4.
5. Capture the input table, full chart, summary cards, and per-process metrics.
   Use a full-page screenshot if they do not fit together on screen.
6. Repeat Scenario B with SJF, then with Round Robin and quantum 2. Compare their
   results with the respective expected values above. Changing algorithms opens
   a new workspace, so re-enter the scenario each time.
7. Run Scenario A for all three policies and compare its expected results.
8. Edit a burst after a successful run: old results should disappear. Run again
   and confirm the new input is reflected. Also change the Round Robin quantum.
9. Try a burst of 0, a duplicate ID, an unsafe arrival such as 9007199254740992,
   and a quantum of 0. Each should show a validation error without a new chart.
10. For a workload check, use bursts 10001, 1, 1 with all arrivals 0 and RR quantum
    1. The run should be rejected. Set quantum to 10000 and verify it succeeds.
11. Add a process, fill in its ID, arrival, and burst, then run again. Remove that
    process and rerun to confirm the output reflects the current rows. Confirm
    the layout remains usable at your planned presentation window size.

Suggested screenshot caption:

> FCFS simulation with out-of-order process inputs, a CPU idle interval from
> time 5 to 10, and the resulting completion, turnaround, waiting, and average times.
